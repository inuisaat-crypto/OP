# JSON-миссии OP — руководство

## Сначала важное

Pybricks Code запускает Python, а не JSON. Поэтому рецепты сначала проверяются
и преобразуются упаковщиком в обычные Python-модули. Тестер умеет выполнять
офлайн dry-run, а также запускать выбранную миссию на Pybricks-хабе по
Bluetooth.

## Быстрый старт

1. Создай файл с именем `missions/mission_3.json` рядом с `mission_1.json`.
2. Скопируй пример из раздела [«Пример целой миссии»](#пример-целой-миссии).
3. Измени название и команды в `steps`.
4. В корне проекта запусти `python mission_tester.py --offline` и затем выбери
   номер файла. Во время просмотра нажми `Ctrl+C`, чтобы остановить.
5. Запусти `python build_archive.py` и открой `missions/OP_pybricks_project.zip`
   в Pybricks Code. В архиве рецепт будет Python-файлом с тем же номером и уже
   появится в меню миссий.

Для реального запуска установи Python 3.10+ и создай отдельное окружение,
чтобы PybricksDev не устанавливался в общий Python:

```powershell
py -3 -m venv .venv-mission-tester
.\.venv-mission-tester\Scripts\python.exe -m pip install -r requirements-mission-tester.txt
.\.venv-mission-tester\Scripts\python.exe mission_tester.py
```

При повторном запуске достаточно последней команды. Тестер сам подключится к
первому найденному хабу и покажет список миссий; выбранная миссия стартует сразу,
без `RUN`. Во время движения нажми `Q` (или `Esc`) для остановки. После
завершения или остановки нажми `1`, чтобы перезапустить эту миссию, или `2`,
чтобы вернуться к списку. Соединение остаётся активным, пока не нажмёшь `q`
в списке миссий. Если загрузка не удалась, тестер предложит повторить её или
вернуться к списку, когда соединение ещё активно. CENTER на хабе остаётся
физическим стопом. Освободи пространство вокруг робота и закрой Pybricks Code
и другие программы, подключённые к хабу. Тестер замечает изменения выбранного
JSON во время работы миссии, но не прерывает её; сохранённая версия будет
загружена при следующем запуске или перезапуске миссии.

Тестер находит файлы `missions/mission_*.json`. Этот справочник не является рецептом и
не появится в списке. Dry-run не учитывает покрытие, препятствия и особенности
навески, а подключение через Bluetooth не гарантирует точность маршрута.
Сборщик проверяет формат и только после этого добавляет Python-миссию в ZIP;
файлы JSON в ZIP не копируются.

## Структура файла

Каждый рецепт — один JSON-объект с четырьмя обязательными полями:

| Поле | Что указать |
| --- | --- |
| `version` | Число `1` — версия формата. |
| `name` | Непустое название миссии. |
| `color` | Цвет меню: `BLACK`, `BLUE`, `CYAN`, `GREEN`, `MAGENTA`, `ORANGE`, `RED`, `VIOLET`, `WHITE` или `YELLOW`. |
| `steps` | Список из 1–200 команд. Они выполняются по порядку. |

Блочный редактор дополнительно сохраняет необязательное поле `start_pose` с
координатами `x_mm` (0–2000), `y_mm` (0–1140) и курсом `heading_deg`
(-360–360). Оно задаёт старт только для карты-предпросмотра; код движения на
роботе начинает отсчёт от его текущего положения. `x_mm` и `y_mm` обозначают
центр робота; на карте его прямоугольный контур имеет размер 183 мм по
горизонтали и 120 мм по вертикали при курсе 0° и поворачивается вместе с
роботом. Размер карты — примерно 200 × 114 см по масштабу PDF: 10 ячеек
шириной по 20 см, с высотой, соответствующей пропорциям схемы.

JSON не поддерживает комментарии. Не добавляй комментарии и запятые после
последнего элемента. Имена полей и типы команд должны быть написаны точно,
лишние поля тестер отклонит.

### Сквозные переходы — `through`

У движений (`straight`, `turn`, `turn_to`, `wheel_turn`, `arc`) есть
необязательное поле `through`: `true` означает «не останавливаться» — runtime
вызовет движение с `then=Stop.NONE`, и следующий шаг продолжит ход без остановки
и без потери времени на разгон.

- Следующая команда тоже должна быть движением: `through` перед `wait`,
  `attachment` или в конце списка тестер отклонит (робот уехал бы без управления).
- Скорости на стыке сглаживаются профилем: следующий `straight` начинает не с
  нуля, а с фактической скорости (`v_start`), поэтому рывка нет.
- Быстрый режим `rush` сам по себе не включается: нужен отдельный шаг
  `{"type": "rush", "enabled": true}`.

## Команды

### Ехать прямо — `straight`

- `distance_mm` — обязательное расстояние в миллиметрах, от `-5000` до `5000`,
  кроме `0`. Отрицательное значение означает движение назад.
- `speed_mm_s` — необязательная скорость от `1` до `800` мм/с. Если поле
  пропущено, используется профиль скорости runtime.

800 мм/с — верхняя граница формата, а не обещание, что робот достигнет такой
скорости. Runtime дополнительно ограничивает её возможностями моторов.

```json
{"type": "straight", "distance_mm": 250, "speed_mm_s": 100}
```

### Поворот на месте — `turn`

- `angle_deg` — обязательный угол от `-360` до `360` градусов, кроме `0`.
  Положительное значение — вправо, отрицательное — влево.
- `rate_deg_s` — необязательная скорость поворота от `1` до `360` градусов/с.
  Если поле пропущено, используется профиль скорости runtime.

```json
{"type": "turn", "angle_deg": 90, "rate_deg_s": 60}
```

### Дуга — `arc`

Дуга позволяет ехать вперёд или назад, одновременно меняя направление.

- `radius_mm` — радиус от `-5000` до `5000` мм, кроме `0`. Знак задаёт
  направление кривизны дуги.
- `angle_deg` — угол от `-360` до `360` градусов, кроме `0`. Положительный
  угол означает движение вперёд, отрицательный — назад.
- `speed_mm_s` — необязательная скорость от `1` до `800` мм/с.
- Длина пути по центру робота примерно равна `abs(radius_mm) * abs(angle_deg)
  * pi / 180`.

При движении назад направление поворота корпуса противоположно кривизне дуги.
Например, `radius_mm: -140.06` и `angle_deg: -45` дают примерно 110 мм назад,
одновременно поворачивая корпус вправо на 45°.

```json
{"type": "arc", "radius_mm": -140.06, "angle_deg": -45, "speed_mm_s": 800}
```

### Поворот на абсолютный курс — `turn_to`

- `heading_deg` — целевой курс от `-360` до `360` градусов.
- `rate_deg_s` — необязательная скорость поворота от `1` до `360` градусов/с.

Курс отсчитывается от стартового направления робота: `0` — как на старте,
`90` — вправо. Полезно, когда после серии дуг нужно вернуться к известному курсу.

```json
{"type": "turn_to", "heading_deg": 0, "rate_deg_s": 90}
```

### Поворот вокруг колеса — `wheel_turn`

- `angle_deg` — угол от `-360` до `360` градусов, кроме `0`. Положительный угол —
  по часовой стрелке.
- `locked` — какое колесо остаётся стоять: `RIGHT` или `LEFT`.
- `rate_deg_s` — необязательная скорость от `1` до `360` градусов/с.

Робот вращается вокруг неподвижного колеса, поэтому центр корпуса смещается —
карта-предпросмотр это учитывает.

```json
{"type": "wheel_turn", "angle_deg": 45, "locked": "RIGHT", "rate_deg_s": 120}
```

### Прижаться к стене — `wall_square`

- `heading_deg` — курс, который удерживается во время прижатия, от `-360` до `360`.
- `duty` — необязательное усилие от `-100` до `100` процентов, кроме `0`.
- `duration_ms` — необязательная длительность от `50` до `3000` миллисекунд,
  по умолчанию `800`.

Смещение при прижатии не моделируется: на карте робот остаётся на месте.

```json
{"type": "wall_square", "heading_deg": 0, "duty": 35, "duration_ms": 800}
```

### Повернуть навеску — `attachment`

- `port` — порт мотора навески: `E` или `F`.
- `angle_deg` — угол от `-360` до `360` градусов, кроме `0`. Знак задаёт
  направление.
- `speed_deg_s` — скорость от `1` до `800` градусов/с.

```json
{"type": "attachment", "port": "E", "angle_deg": 90, "speed_deg_s": 90}
```

### Навеска до упора — `att_until_stalled`

- `port` — порт мотора навески: `E` или `F`.
- `speed_deg_s` — скорость от `-1000` до `1000` градусов/с, кроме `0`.
- `duty_limit` — необязательный предел момента от `1` до `100` процентов.

Мотор крутится, пока не упрётся: удобно для захватов и подъёмов без точного угла.

```json
{"type": "att_until_stalled", "port": "E", "speed_deg_s": 400, "duty_limit": 80}
```

### Ускорение навески — `set_att_accel`

- `accel_deg_s2` — ускорение от `10` до `2000` градусов/с².

Настройка действует на все последующие движения навесок до конца миссии.

```json
{"type": "set_att_accel", "accel_deg_s2": 600}
```

### Пауза — `wait`

- `duration_ms` — целое число от `0` до `30000` миллисекунд.

```json
{"type": "wait", "duration_ms": 500}
```

### Звуковой сигнал — `beep`

- `frequency_hz` — целая частота от `50` до `4000` герц.
- `duration_ms` — целая длительность от `1` до `1000` миллисекунд.

Сигнал идёт через `core.beep()`, поэтому при `DEBUG_BEEP = False` (боевой режим)
блок молчит и не тратит время; при отладке звучит как обычно.

```json
{"type": "beep", "frequency_hz": 880, "duration_ms": 150}
```

### Запись в лог — `log`

- `message` — строка от `1` до `120` символов. Печатается в консоль хаба, удобно
  помечать контрольные точки при отладке.

```json
{"type": "log", "message": "точка 1"}
```

### Проверка заряда — `battery_check`

Полей нет. Runtime измеряет напряжение батареи и пишет его в лог.

```json
{"type": "battery_check"}
```

### Профиль скорости — `set_speed`

- `profile` — `FAST`, `MEDIUM`, `SLOW` или `SLOWW`.

Меняет профиль всех последующих движений до конца миссии; на уже начатое
движение не влияет.

```json
{"type": "set_speed", "profile": "SLOW"}
```

### Опорный курс — `set_heading`

- `heading_deg` — курс от `-360` до `360`, который считается текущим.

После сброса следующие `turn` и `straight` отсчитываются от нового нуля.

```json
{"type": "set_heading", "heading_deg": 0}
```

### Быстрый режим — `rush`

- `enabled` — `true` или `false`. Включает ускоренный возврат в базу в конце
  миссии; выключается тем же блоком.

```json
{"type": "rush", "enabled": true}
```

### Стоп — `stop`

- `scope` — `drive` (остановить только привод), `all` (привод и навески) или
  `release` (отпустить привод без удержания).

```json
{"type": "stop", "scope": "drive"}
```

### Сброс на старт — `reset_start`

Полей нет. Сбрасывает внутренние счётчики runtime перед следующей попыткой.

```json
{"type": "reset_start"}
```

### Условие — `if`

Условие проверяется на роботе. Доступны `heading_deg`, `battery_mv` и
`attachment_angle_deg` (для последнего укажи `port`: `E` или `F`), операторы
`<`, `<=`, `==`, `!=`, `>=`, `>`. Ветка `then` обязательна; `else` можно
опустить. Каждая указанная ветка должна содержать хотя бы одну команду.

```json
{
  "type": "if",
  "condition": {"sensor": "heading_deg", "operator": "<", "value": 20},
  "then": [{"type": "straight", "distance_mm": 100}],
  "else": [{"type": "turn", "angle_deg": 90}]
}
```

### Повтор — `repeat`

`times` — число повторов от 1 до 100, `steps` — команды внутри цикла.

```json
{
  "type": "repeat",
  "times": 3,
  "steps": [{"type": "straight", "distance_mm": 50}]
}
```

### Параллельное выполнение — `parallel`

Укажи минимум две разные дорожки ресурсов. Дорожка `drive` содержит движения
и/или паузу; дорожка `E` или `F` содержит ровно одну команду соответствующей
навески. Навеска запускается одновременно с приводом, затем runtime дожидается
её завершения. Две дорожки привода не допускаются.

```json
{
  "type": "parallel",
  "branches": [
    {"resource": "drive", "steps": [{"type": "straight", "distance_mm": 200}]},
    {
      "resource": "F",
      "steps": [{"type": "attachment", "port": "F", "angle_deg": 90, "speed_deg_s": 300}]
    }
  ]
}
```

Терминальный dry-run показывает обе возможные ветки `if`, потому что компьютер
не подключён к датчикам и мотору. Это проверка маршрутов, а не физическая
симуляция. Параллельный блок на карте показывает только дорожку привода.

## Пример целой миссии

Команды выполняются по порядку: проехать 200 мм, повернуть направо на 90°,
повернуть мотор навески E на 45°, подождать и подать сигнал.

```json
{
  "version": 1,
  "name": "Квадрат и навеска",
  "color": "CYAN",
  "steps": [
    {"type": "straight", "distance_mm": 200, "speed_mm_s": 100},
    {"type": "turn", "angle_deg": 90, "rate_deg_s": 60},
    {"type": "attachment", "port": "E", "angle_deg": 45, "speed_deg_s": 90},
    {"type": "wait", "duration_ms": 300},
    {"type": "beep", "frequency_hz": 880, "duration_ms": 150}
  ]
}
```

## Советы перед запуском

- Сначала проверяй рецепт с небольшой скоростью и короткими перемещениями.
- Убедись, что робот и навеска могут свободно двигаться по маршруту.
- Если тестер сообщает об ошибке, сверь тип команды, обязательные поля,
  допустимые значения и единицы измерения.
- При совпадении имён JSON является источником миссии для архива: например,
  `mission_3.json` создаёт `mission_3.py`. Пересобери ZIP после каждого изменения.
