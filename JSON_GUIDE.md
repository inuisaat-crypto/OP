# JSON-миссии OP — руководство

## Сначала важное

Pybricks Code запускает Python, а не JSON. Поэтому рецепты сначала проверяются
и преобразуются упаковщиком в обычные Python-модули. Тестер умеет выполнять
офлайн dry-run, а также запускать выбранную миссию на Pybricks-хабе по
Bluetooth.

## Быстрый старт

1. Создай файл с именем `mission_3.json` рядом с `mission_1.json`.
2. Скопируй пример из раздела [«Пример целой миссии»](#пример-целой-миссии).
3. Измени название и команды в `steps`.
4. В корне проекта запусти `python mission_tester.py`, выбери `Offline dry-run`
   и затем номер файла. Во время просмотра нажми `Ctrl+C`, чтобы остановить.
5. Запусти `python build_archive.py` и открой `OP_pybricks_project.zip` в
   Pybricks Code. В архиве рецепт будет Python-файлом с тем же номером и уже
   появится в меню миссий.

Для реального запуска установи Python 3.10+ и создай отдельное окружение,
чтобы PybricksDev не устанавливался в общий Python:

```powershell
py -3 -m venv .venv-mission-tester
.\.venv-mission-tester\Scripts\python.exe -m pip install -r requirements-mission-tester.txt
.\.venv-mission-tester\Scripts\python.exe mission_tester.py
```

При повторном запуске достаточно последней команды. Выбери Bluetooth-режим:
сначала подключись к хабу, затем выбери JSON и введи `RUN`. Во время движения
`Esc` отправляет команду остановки, а CENTER на хабе остаётся физическим
стопом. Освободи пространство вокруг робота и закрой Pybricks Code и другие
программы, подключённые к хабу.

Тестер находит файлы `mission_*.json`. Этот справочник не является рецептом и
не появится в списке. Dry-run не учитывает покрытие, препятствия и особенности
навески, а подключение через Bluetooth не гарантирует точность маршрута.
Сборщик проверяет формат и только после этого добавляет Python-миссию в ZIP;
файлы JSON в ZIP не копируются.

## Структура файла

Каждый рецепт — один JSON-объект с четырьмя обязательными полями:

| Поле | Что указать |
| --- | --- |
| `version` | Число `1` — версия формата. |
| `name` | Непустое название миссии. |
| `color` | Цвет меню: `BLACK`, `BLUE`, `CYAN`, `GREEN`, `MAGENTA`, `ORANGE`, `RED`, `VIOLET`, `WHITE` или `YELLOW`. |
| `steps` | Список из 1–200 команд. Они выполняются по порядку. |

Блочный редактор дополнительно сохраняет необязательное поле `start_pose` с
координатами `x_mm` (0–1100), `y_mm` (0–2300) и курсом `heading_deg`
(-360–360). Оно задаёт старт только для карты-предпросмотра; код движения на
роботе начинает отсчёт от его текущего положения.

JSON не поддерживает комментарии. Не добавляй комментарии и запятые после
последнего элемента. Имена полей и типы команд должны быть написаны точно,
лишние поля тестер отклонит.

## Команды

### Ехать прямо — `straight`

- `distance_mm` — обязательное расстояние в миллиметрах, от `-5000` до `5000`,
  кроме `0`. Отрицательное значение означает движение назад.
- `speed_mm_s` — необязательная скорость от `1` до `800` мм/с. Если поле
  пропущено, используется профиль скорости runtime.

800 мм/с — верхняя граница формата, а не обещание, что робот достигнет такой
скорости. Runtime дополнительно ограничивает её возможностями моторов.

```json
{"type": "straight", "distance_mm": 250, "speed_mm_s": 100}
```

### Поворот на месте — `turn`

- `angle_deg` — обязательный угол от `-360` до `360` градусов, кроме `0`.
  Положительное значение — вправо, отрицательное — влево.
- `rate_deg_s` — необязательная скорость поворота от `1` до `360` градусов/с.
  Если поле пропущено, используется профиль скорости runtime.

```json
{"type": "turn", "angle_deg": 90, "rate_deg_s": 60}
```

### Дуга — `arc`

Дуга позволяет ехать вперёд или назад, одновременно меняя направление.

- `radius_mm` — радиус от `-5000` до `5000` мм, кроме `0`. Знак задаёт
  направление кривизны дуги.
- `angle_deg` — угол от `-360` до `360` градусов, кроме `0`. Положительный
  угол означает движение вперёд, отрицательный — назад.
- `speed_mm_s` — необязательная скорость от `1` до `800` мм/с.
- Длина пути по центру робота примерно равна `abs(radius_mm) * abs(angle_deg)
  * pi / 180`.

При движении назад направление поворота корпуса противоположно кривизне дуги.
Например, `radius_mm: -140.06` и `angle_deg: -45` дают примерно 110 мм назад,
одновременно поворачивая корпус вправо на 45°.

```json
{"type": "arc", "radius_mm": -140.06, "angle_deg": -45, "speed_mm_s": 800}
```

### Повернуть навеску — `attachment`

- `port` — порт мотора навески: `E` или `F`.
- `angle_deg` — угол от `-360` до `360` градусов, кроме `0`. Знак задаёт
  направление.
- `speed_deg_s` — скорость от `1` до `800` градусов/с.

```json
{"type": "attachment", "port": "E", "angle_deg": 90, "speed_deg_s": 90}
```

### Пауза — `wait`

- `duration_ms` — целое число от `0` до `30000` миллисекунд.

```json
{"type": "wait", "duration_ms": 500}
```

### Звуковой сигнал — `beep`

- `frequency_hz` — целая частота от `50` до `4000` герц.
- `duration_ms` — целая длительность от `1` до `1000` миллисекунд.

```json
{"type": "beep", "frequency_hz": 880, "duration_ms": 150}
```

### Условие — `if`

Условие проверяется на роботе. Доступны `heading_deg`, `battery_mv` и
`attachment_angle_deg` (для последнего укажи `port`: `E` или `F`), операторы
`<`, `<=`, `==`, `!=`, `>=`, `>`. Ветка `then` обязательна; `else` можно
опустить. Каждая указанная ветка должна содержать хотя бы одну команду.

```json
{
  "type": "if",
  "condition": {"sensor": "heading_deg", "operator": "<", "value": 20},
  "then": [{"type": "straight", "distance_mm": 100}],
  "else": [{"type": "turn", "angle_deg": 90}]
}
```

### Повтор — `repeat`

`times` — число повторов от 1 до 100, `steps` — команды внутри цикла.

```json
{
  "type": "repeat",
  "times": 3,
  "steps": [{"type": "straight", "distance_mm": 50}]
}
```

### Параллельное выполнение — `parallel`

Укажи минимум две разные дорожки ресурсов. Дорожка `drive` содержит движения
и/или паузу; дорожка `E` или `F` содержит ровно одну команду соответствующей
навески. Навеска запускается одновременно с приводом, затем runtime дожидается
её завершения. Две дорожки привода не допускаются.

```json
{
  "type": "parallel",
  "branches": [
    {"resource": "drive", "steps": [{"type": "straight", "distance_mm": 200}]},
    {
      "resource": "F",
      "steps": [{"type": "attachment", "port": "F", "angle_deg": 90, "speed_deg_s": 300}]
    }
  ]
}
```

Терминальный dry-run показывает обе возможные ветки `if`, потому что компьютер
не подключён к датчикам и мотору. Это проверка маршрутов, а не физическая
симуляция. Параллельный блок на карте показывает только дорожку привода.

## Пример целой миссии

Команды выполняются по порядку: проехать 200 мм, повернуть направо на 90°,
повернуть мотор навески E на 45°, подождать и подать сигнал.

```json
{
  "version": 1,
  "name": "Квадрат и навеска",
  "color": "CYAN",
  "steps": [
    {"type": "straight", "distance_mm": 200, "speed_mm_s": 100},
    {"type": "turn", "angle_deg": 90, "rate_deg_s": 60},
    {"type": "attachment", "port": "E", "angle_deg": 45, "speed_deg_s": 90},
    {"type": "wait", "duration_ms": 300},
    {"type": "beep", "frequency_hz": 880, "duration_ms": 150}
  ]
}
```

## Советы перед запуском

- Сначала проверяй рецепт с небольшой скоростью и короткими перемещениями.
- Убедись, что робот и навеска могут свободно двигаться по маршруту.
- Если тестер сообщает об ошибке, сверь тип команды, обязательные поля,
  допустимые значения и единицы измерения.
- При совпадении имён JSON является источником миссии для архива: например,
  `mission_3.json` создаёт `mission_3.py`. Пересобери ZIP после каждого изменения.
